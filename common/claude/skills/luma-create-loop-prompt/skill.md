# loop プロンプトの作成

実際に設計、開発と進めていくためのプロンプトそのもののみを `/loop` から始まる `loop-prompt.txt` ファイルで開発ドキュメント群の中に配置する。

## 原則

- プロジェクトの知識は入れない。参照のみさせる。プロンプト内にドメイン知識やコード構造を埋め込まず、ドキュメントファイルのパスを指定して読ませる
- 進めかたは `/luma-web-insert-task` のステータス管理を利用する。タスクの洗い出し・分解・ステータス遷移はそのスキルに従う。参照先ドキュメントのパスを具体的に示す
- 1 回の実行で 1 ステート分だけ。まとめてやらない
- 変更があれば必ずコミットする。1 ステート分の実装が終わったら、進捗更新とあわせてコミットまで行う
- 実装状況の共有にはファイルを使う。未完了タスクとステータスは {tasks md} に、done になったタスクは {tasks done md} に移して書き出し、次回ループや他セッションから参照できるようにする。{tasks md} を未完了分だけに保ち、毎回の読み込みを軽くする

## 手順

1. ドキュメント構造の把握: プロジェクトの開発ドキュメント群（設計書、タスクリスト、完了タスクの記録等）の場所と構造を確認する
2. 参照先の特定: ループプロンプトが読むべきドキュメントのパスを特定する
3. loop-prompt.txt の作成: 開発ドキュメント群の中に配置する

## 標準形

以下を標準形として、プロジェクトに合わせてパスや詳細を調整する:

```
/loop 5m dev/ 配下のドキュメントと {tasks md} を読め。次にやるべきことの洗い出し・タスク分解・ステート管理は /luma-web-insert-task を使え。ステータスは draft → design → implementing → testing → QA✓ → review✓ → meta-review✓ → done の順に遷移させ、✓ が不合格なら design か implementing に差し戻せ（差し戻しは別の実行で行い、ついでに直さない）。未完了タスクがあればその中で最優先の 1 つを 1 ステート分だけ進めよ。完了後 {tasks md} と {tasks done md} を更新し、変更があればコミットせよ。
```

### 構成要素

| 要素 | 説明 |
|---|---|
| `/loop 5m` | 5分間隔で繰り返し実行 |
| ドキュメント読み込み | `dev/` 配下のドキュメントと {tasks md} を毎回読む |
| タスク管理 | `/luma-web-insert-task` ({より詳細な参照箇所}) でタスクの洗い出し・分解・ステート管理 |
| ステータス遷移 | `/luma-web-insert-task` のステータスフローと差し戻し規則を明記する。スキル側を変更したらここと標準形も合わせて更新する |
| 実装範囲 | 未完了タスクの最優先 1 つを 1 ステート分だけ |
| 進捗更新 | 完了後に {tasks md} のステータスを更新し、done になったタスクは {tasks done md} へ移す |
| コミット | 変更があれば必ずコミットする |

## 調整のポイント

- ドキュメントディレクトリのパス（`dev/` → `docs/`, `design/` 等）
- {tasks md} と {tasks done md} のパス（既存のタスク管理ファイルがあればそれを使う）
- `/luma-web-insert-task` に渡す参照箇所の具体化（タスクリストファイル、設計書等のパス）
- ループ間隔（`5m` は標準。タスク粒度に応じて調整）

## 完了条件

- `loop-prompt.txt` が開発ドキュメント群の中に配置された
- ファイルの中身が `/loop` から始まるプロンプトのみである
- プロジェクト固有の知識が埋め込まれておらず、参照パスのみで構成されている
