プロジェクトのすべてのgit trackedファイルを対象に、指示された作業を網羅的に実行する。進捗状態を `exhaust-{name}.ignore.md`（例: `exhaust-type-review.ignore.md`）で管理し、見落としゼロを保証する。

## 入力

ユーザーから以下を受け取る:

- 作業内容: 各ファイルに対して行う作業（例: レビュー、リファクタ、型修正、lint修正、命名統一）
- スコープ制限（任意）: 特定ディレクトリやファイルパターンに絞る場合

## 手順

### 1. ファイルリスト取得

```bash
git ls-files
```

これが唯一の正（git trackedファイルのみが対象）。`.gitignore` 済みファイル、untracked ファイルは対象外。

### 2. 進捗管理ファイルの作成・確認

プロジェクトルートに `exhaust-{name}.ignore.md` を作成する（既に存在すれば読み込んで続行）。

#### フォーマット

ファイルエクスプローラ方式で管理する。最初はトップレベルのディレクトリ・ファイルだけを折りたたんだ状態で列挙し、作業しながら展開していく。

```markdown
# Exhaust: [作業名]

## 発見事項サマリ

作業中に発見した重要な事項をここに蓄積する。会話コンテキストに依存せず、この進捗ファイルが single source of truth。再開時にこのセクションを読むだけで、過去の発見を完全に把握できる状態を保つ。

- [発見1: 何を、どのファイルで発見し、どう対処したか（または未対処か）]
- [発見2: ...]

## Loop

\`\`\`
/loop 10m /luma-exhaust exhaust-{name}.ignore.md の続きをやる: [作業の要約]
\`\`\`

## ツリー

- [x] src/
  - [x] src/utils/          # 完了: 3 files
  - [ ] src/components/
    - [x] Button.tsx
    - [ ] Modal.tsx
    - [ ] Form.tsx
  - [ ] src/hooks/
- [x] tests/                # 完了: 5 files
- [x] package.json
- [ ] tsconfig.json
```

#### 3つの状態

| 表記 | 意味 |
|------|------|
| `- [ ] dir/` | 折りたたみ（未着手）: 中身は未展開。まだ見ていない |
| `- [ ] dir/` + 子要素あり | 展開中（作業中）: 中身を展開して個別に処理している |
| `- [x] dir/  # 完了: N files` | 折りたたみ（完了）: 全ファイル完了。子要素は削除してコメントに件数だけ残す |

ファイルにも同じチェックボックスを使う:

| 表記 | 意味 |
|------|------|
| `- [ ] file.tsx` | 未完了 |
| `- [x] file.tsx` | 完了 |
| `- [x] file.tsx  # skip: 理由` | スキップ（理由付き） |

#### 進行ルール

1. 初期状態: `git ls-files` からトップレベルのディレクトリとファイルだけを `[ ]` で列挙する。中身は書かない
2. 展開: 次に作業するディレクトリを選び、`git ls-files dir/` でその直下の子（ファイルとサブディレクトリ）を展開する。サブディレクトリはさらに折りたたんだまま
3. 作業: 展開されたファイルを上から順に Read → 作業 → `[x]` にする
4. 折りたたみ: ディレクトリ内の全ファイル・全サブディレクトリが `[x]` になったら、子要素を消して `- [x] dir/  # 完了: N files` にまとめる
5. 次へ: 残りの `[ ]` ディレクトリ/ファイルに進む
6. 上から順: 基本的にツリーの上から順に処理する。依存関係がある場合はその限りではない

1ターンで展開するのは1-2ディレクトリまで。処理したファイルのチェックを都度更新し、中断に備える。ターン内で処理しきれないものは折りたたんだまま次に渡す。

### 3. 中断・再開

会話が切れても `exhaust-{name}.ignore.md` が状態を保持している。再開時は:

1. `exhaust-{name}.ignore.md` を読む
2. 展開済みの未完了ファイル (`[ ]`) があればそこから続行
3. なければ次の折りたたみディレクトリを展開して続行

## 最初のショット

skill 呼び出し直後の最初のショットでは、実際の作業を開始しない。以下の整理のみを行う:

1. 作業内容とスコープを確認する
2. `git ls-files` でファイルリストを取得する
3. 進捗ファイル (`exhaust-{name}.ignore.md`) を作成し、トップレベルのツリーを列挙する
4. 作業の進め方（順序、スキップ基準など）を明示する

整理が完了したら、ユーザーに確認を取ってから次のショットで作業を開始する。

## 注意事項

- `exhaust-*.ignore.md` は `.gitignore` に追加する必要はない。`*.ignore.*` パターンでgitにtrackされない想定（プロジェクトの `.gitignore` を確認し、必要なら追加を提案すること）
- 作業完了の判断は厳密に: ファイルを Read で確認せずに `[x]` にしない
- スキップする場合は理由を書く: 対象外と判断したファイル（バイナリ、自動生成、lock fileなど）は `[x] path  # skip: 理由` で残す
- `exhaust-{name}.ignore.md` 自体が進捗のsingle source of truth: 他に状態を持たない
- ツリーは常にコンパクトに保つ: 完了ディレクトリは折りたたむ。未着手ディレクトリは展開しない。ファイルに同時に見えるのは「作業中の展開部分」だけ

## 完了条件

- `exhaust-{name}.ignore.md` のすべてのトップレベル項目が `[x]` になっている
