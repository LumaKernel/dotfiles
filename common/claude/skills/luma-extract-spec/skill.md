$ARGUMENTS で指定された対象の仕様を、specファイルとして記述する。

## specファイルの配置

対象が何かは $ARGUMENTS で決まっている。聞くのは置き場所だけ。

- 既存のspecファイルやドキュメントディレクトリがないか Glob で探す (spec/, docs/, etc.)
- 候補パスをユーザーに提示し、確定してから書く。勝手に決めない
- 標準は `spec/{name}.md`。docs/ 等の既存ディレクトリがあればその配下を優先候補にする

## 仕様の収集

- 対象のコードを読む。実装から仕様を逆算する
- git log で対象に関連するコミットを確認する
  - 追加コミット（初回実装後の変更）に特に注目する。後から足された仕様は見落としやすく、かつ意図的に追加されたものなので重要度が高い
- テストがあれば読む。テストは暗黙の仕様書

## 書き方

- 箇条書きのみ。章立て不要
- 結論のみ書く。理由・経緯・背景は書かない
- 強調（太字・斜体）は使わない
- 自明なこと（「エラー時はエラーを返す」等）は書かない
- 非自明な振る舞い、エッジケース、暗黙の前提条件に集中する
- 挨拶・前置き・まとめは書かない
- コード例は、言葉で説明するより短く正確な場合のみ使う
