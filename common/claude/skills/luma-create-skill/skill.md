# スキルの作成

新しい skill.md を作成する。

## 入力

ユーザーから以下を受け取る:

- スキルの目的・やりたいこと
- 配置先: 以下のいずれか
  - プロジェクトローカル (`.claude/skills/<name>/skill.md`)
  - ユーザースペース (`~/.claude/skills/<name>/skill.md`)
  - cwd 配下にユーザースペースのスキル群を管理するリポジトリがある場合（例: dotfiles）は、そのリポジトリ内のパスを対象とする

配置先が不明な場合は、cwd の構造を確認し、ユーザースペースのスキルを管理していそうなディレクトリがあればそちらを提案する。なければ聞く。

## スキルを書くときの原則

スキルは「進めかた」「管理の仕方」だけを書く。そのスキルを使う場面で、どういう手順で、何をどう管理しながら進めるかの手続きだけに集中する。

書かないもの:

- 一般論。ソフトウェア開発の常識、ベストプラクティス、心構えのようなものは書かない。読み手がそれを知らない前提に立たない
- 言わなくても考えれば分かること。文脈から自明に導ける判断基準やチェック項目は書かない
- 装飾。強調（太字・斜体）は使わない。プレーンテキストとして読めるように書く

書くもの:

- このスキルでしか生まれない手順・判断基準・管理方法
- 具体的なファイルパス、コマンド、フォーマットの指定
- 進行の状態管理（ある場合）
- 完了条件

## 手順

1. 配置先を決める
2. 既存スキルのスタイルを確認する（配置先ディレクトリ内の他のスキルを数個読む）
3. frontmatter（name, description, allowed-tools）を決める
   - description は1行で、スキルリストに表示されたときに目的が伝わるように書く
   - allowed-tools は必要最小限にする
4. 本文を書く。上記の原則に従い、進めかたと管理の仕方だけを書く
5. 書き終えたら読み返し、一般論・自明なこと・強調表現がないか確認して削る

## 完了条件

- skill.md が配置先に作成されている
- frontmatter の name, description が埋まっている
- 本文に一般論、自明な記述、強調表現が含まれていない
- 本文が「進めかた」「管理の仕方」に集中している
